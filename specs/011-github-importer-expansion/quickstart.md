# Quickstart: GitHub Importer Expansion

**Date**: 2026-09-13 | **Spec**: [spec.md](spec.md)

Runnable validation that the feature works end-to-end. Implementation details
live in `tasks.md` (generated by `/speckit-tasks`).

## Prerequisites

- Repo built: `pnpm install && pnpm -r build`
- Postgres running (docker-compose or testcontainers for tests)
- A GitHub PAT — `read:org` minimum; org-admin to exercise billing paths
- A test GitHub org with at least one repo that has environments/deployments

## Automated checks

```bash
# Unit tests — mock fetch router covers every endpoint
pnpm --filter @componode/importer-github test

# Core + backend: new ACCOUNT category + CHECK migration
pnpm --filter @componode/core test
pnpm --filter @componode/backend test

# Typecheck + build
pnpm -r typecheck && pnpm -r build
```

Expected: all green; migration `010_account_category` applies and rolls back
cleanly; every emitted asset passes `validateDiscoveredAsset`.

## Manual validation scenarios

### S1 — Organization asset (US1)

1. Create importer config: importer `github`, org `<your-org>`,
   token env `GITHUB_TOKEN`.
2. Trigger a run.
3. **Verify**: catalog shows one `ACCOUNT`/`github:organization` component
   named for the org; details contain `plan` (seats filled/total),
   `policies.twoFactorRequired`, and a `teams` array with member counts.

### S2 — Deployment topology (US2)

1. On the same config set `environmentMapping` to include `main=PRODUCTION`.
2. Ensure a repo has GitHub environments `staging` + `prod` with deployments.
3. Run. **Verify**: repo component shows a `PRODUCTION` branch instance for
   `main`, plus `STAGING` and `PRODUCTION` environment instances with
   deployment-derived version/deployedAt. A repo with no mapped branches and
   no environments shows zero instances.
4. Rename the repo on GitHub, re-run. **Verify**: same component updated in
   place — no duplicate, ownership preserved.

### S3 — Billing visibility (US3)

1. With an org-admin token: run and open the org component.
   **Verify**: `details.billing.status === "OK"` with `totals`, `byProduct`,
   `topRepos`; attributed repos carry `details.billing`.
2. With a `read:org`-only token: run.
   **Verify**: `details.billing.status === "FORBIDDEN"`; run completes
   successfully.

### S4 — Optional emitters + GHES (US4)

1. Enable `includeWorkflows`, `includeRunners`, `includePackages`; run.
   **Verify**: `JOB`, `COMPUTE`, `PACKAGE_REGISTRY` components appear.
2. Disable `includeWorkflows`; run. **Verify**: workflow components retire.
3. With GHES: set `baseUrl` to `https://<ghes-host>/api/v3`; run.
   **Verify**: identical behavior; billing marked `UNAVAILABLE`.
4. Set `baseUrl` to `https://10.0.0.1/api/v3`.
   **Verify**: config validation rejects it (URL safety).

### S5 — Rate-limit observability

1. Run against a large org.
2. **Verify**: run logs contain the API budget at start and end; run phase
   progress reports each section.
