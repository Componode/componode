# Repository Research Facts

Read-only fact inventory for the Playwright workload. Re-check the cited source files when implementation begins; the current 055 worktree is based on the committed 053 state and does not contain uncommitted 054 changes.

## Existing test and runtime setup

- The repository has no Playwright Test dependency, config, or E2E suite in the committed 053 base.
- The root workspace is pnpm 9.15.2, Node 24+, and includes the root package plus `packages/*`. A nested `playwright/pnpm-workspace.yaml` keeps the test runner and lockfile standalone.
- Backend integration tests use Testcontainers with PostgreSQL 16.11 and run Kysely migrations from the backend migration directory.
- Root Compose services include PostgreSQL, the app, Caddy, and an optional Import Agent. The app is published at `PORT` (default 3000); Caddy uses `HTTP_PORT` and `HTTPS_PORT` (default 80/443). Named volumes are scoped by the Compose project.
- Root Dockerfile builds the app from repository root. Root `.dockerignore` already includes `**/.env*`, which matches nested test environment files and a `.env-private/` directory. Do not modify the root workspace, Dockerfile, `.dockerignore`, or CI for this exercise.
- `.dockerignore` does not exclude the entire future `playwright/` directory; only generated private env/certificate files must be kept in a path matched by `**/.env*`. The test image is disposable and the remaining non-secret Playwright files may enter its build context.

## Application routes, roles, and user journeys

- Frontend user areas: authentication; dashboard/search; products; components and URL Checks; Component Groups; Suggestions; importer configs/runs; Sources; Docker targets; Import Agents; credentials; Lines of Business; Teams; Users; sessions; activity; settings.
- Roles are Viewer, Editor, and Admin. Admin-only areas include users, settings/OIDC, importer configs, credentials, agents, Docker targets, and audit feed. Editors can author catalog/product content and trigger/cancel importer runs.
- The current permission contract treats non-null Credential selection and Agent-vantage selection as Admin actions. Editors may preserve unchanged Admin-selected configuration while editing unrelated fields, and may switch an Agent setup back to Hub.
- The 054 branch adds focused first-instance recovery for an active Component with zero Component Instances. It does not add general instance CRUD. The action is hidden for non-active Components.
- Password login is rate-limited; setup should log in once per role and reuse isolated browser contexts. Registration is disabled unless enabled in settings. Password reset is generated by an Admin; there is no public forgot-password page.
- OIDC is an optional admin-configured authorization-code flow using PKCE S256 and verified ID-token signatures/JWKS. A local Dex provider is the agreed test provider.

## Pagination facts

- `GET /api/v1/components`: page default 1; pageSize default 50, maximum 100. Frontend `useAllComponents` requests 100 and continues until all pages are fetched. There are no visible pagination buttons.
- `GET /api/v1/audit/activity` and `GET /api/v1/suggestions`: limit default 50, maximum 200; offset default 0.
- Other current UI lists have no server-side pagination params.
- Use Playwright's API request context for page/offset assertions, and browser assertions for actual rendering/loading behavior.

## URL Check and Import Agent facts

- A new enabled Hub check sets `nextProbeAt` to now and is processed on the next sweep. `URL_CHECK_SWEEP_INTERVAL_MS` defaults to 15 seconds and can be set to 1000 for tests.
- The URL safety validator blocks localhost names and private/loopback IP literals, but does not resolve DNS. A `.test` Compose network alias can therefore resolve locally while the configured URL remains a permitted hostname.
- A connected Import Agent initiates an outbound WSS stream. Non-loopback Hub URLs require HTTPS/WSS and a trusted CA; there is no skip-verification option.
- A URL Check observation stores outcome/status/duration/error/vantage, not request headers. Application logs record check ID, outcome, and error type, not secrets.
- A configured-but-disconnected Agent can exercise offline/missed behavior without stopping a container from inside the browser runner.
