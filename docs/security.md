# Security design

::: warning Educational project
Componode is a personal learning project, not a production-grade solution.
This page describes the security decisions the codebase explores — it is
learning material, not an operational hardening guide.
:::

Security was treated as a first-class design constraint from the foundation
spec rather than retrofitted. The binding rules live in ADRs 084–102 and the
project constitution; this page summarizes what the code actually does.

## Authentication & sessions

- **Local auth** — Argon2id password hashing (`@node-rs/argon2`), server-side
  sessions with cryptographically random session IDs (not UUIDs — ADR-099).
- **OIDC SSO** — optional single sign-on with full ID-token verification
  (signature, issuer, audience, expiry, nonce, PKCE).
- **CSRF** — state-changing requests require the `componode_csrf` cookie plus
  a matching `x-csrf-token` header, in addition to the session cookie.
- **RBAC** — route-level `requireRole` enforcement; permissions are declared
  per-route in `docs/openapi.yaml` (`x-permission`) and verified by a backend
  contract test.

## Data & API safety

- **Parameterized queries only** — Kysely everywhere; no `sql.raw()` or
  string-built SQL in application code (ADR-084).
- **Input validation** — Zod schemas at every route boundary; unknown fields
  rejected (ADR-095).
- **Error shape** — `{code, message, details?}` with controlled codes from
  `packages/core`; responses never leak stack traces, SQL, or paths
  (ADR-096).
- **Safe rendering** — no `dangerouslySetInnerHTML`; every URL `href`
  validated with `safeUrl()` (ADR-085).
- **Side-effect-free reads** — `GET`/`HEAD` routes never mutate domain state
  (ADR-094).
- **Auth coverage** — every API route is authenticated except public auth
  routes, `/metrics`, and `/api/v1/health` (ADR-097).

## Secrets

- **Credential store** — integration secrets (importer credentials, OIDC
  client secrets) live in the `credentials` table, AES-256-GCM encrypted,
  write-only over the API (ADR-107).
- **Agent-managed credentials** — for Import Agents, the hub stores reference
  names only (`{env: "…"}`, `{file: "…"}`); secret material never crosses the
  wire and file refs are confined to `SECRETS_DIR` via `realpath`.
- **No secrets in logs** — redaction rules in ADR-090/091; `*_FILE` env vars
  preferred over plain env vars everywhere.

## Infrastructure

- **Rate limiting** and structured Pino logging from the foundation spec.
- **Observability without exposure** — `/metrics` and `/api/v1/health` are
  unauthenticated by design (container health checks, Prometheus scraping)
  and serve no domain data or secrets.
- **Dependency hygiene** — `pnpm audit --prod --audit-level=high` enforced
  in CI; CodeQL and dependency review gate changes.

## Security assessments

Dated read-only assessment reports (generated by the repo's
`security-assessment` skill) are kept in the repository at
`researches/security/`. They document the project's security review history —
including findings that were remediated — and are internal artifacts rather
than user documentation.
